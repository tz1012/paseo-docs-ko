# 작업공간

Paseo는 채팅이 아닌 작업 공간을 중심으로 구성됩니다.

작업공간은 작업이 수행되는 장소입니다. 여기에는 작업 디렉터리가 있으며 동시에 실행되는 여러 세션이 포함될 수 있습니다. 앱에서 각 세션은 탭으로 열립니다.

## 프로젝트에는 작업 공간이 포함되어 있습니다.

사이드바는 프로젝트로 시작됩니다. 프로젝트는 git 저장소, GitHub 프로젝트 또는 Paseo 데몬을 실행하는 머신의 모든 디렉터리일 수 있습니다.

각 프로젝트 내부에는 작업 공간이 있습니다. 예를 들면:

```
my-app
├── main
├── fix-login-flow
└── redesign-settings
```

각 작업 공간은 작업을 위한 별도의 장소입니다. 기본 체크아웃을 위해 하나를 유지하거나, 기능을 위해 또 하나를 생성하거나, GitHub PR을 다른 작업 공간으로 열 수 있습니다.

## 작업공간에는 세션이 포함되어 있습니다.

에이전트는 작업 영역 내에서 세션으로 실행됩니다. 작업 영역에는 하나의 에이전트 세션, 여러 에이전트 세션, 터미널, 브라우저 및 차이점이 동시에 열려 있을 수 있습니다.

실제 개발이 하나의 긴 대화에 들어맞는 경우가 거의 없기 때문에 이는 중요합니다. 한 에이전트에게 기능을 구현하고, 터미널을 열어 서비스를 실행하고, 다른 에이전트를 시작하여 차이점을 검토하고, 두 에이전트 옆에 브라우저를 열어 두도록 요청할 수 있습니다. 그것들은 모두 동일한 작업의 일부이기 때문에 함께 속합니다.

Paseo에서 작업공간은 안정적인 컨테이너입니다. 세션은 그 안에서 실행되는 것입니다.

## 격리를 선택하세요

모든 작업공간에는 격리 모드가 있습니다.

- **로컬**은 기본 결제와 같은 기존 디렉터리를 사용합니다. 세션이 이미 디스크에 있는 파일을 공유해야 할 때 사용하세요.
- **Worktree**는 관리되는 Git 작업 트리를 생성하거나 엽니다. 작업에 자체 디렉터리와 분기가 필요할 때 사용하세요.

작업 공간은 제품 컨셉입니다. git 작업 트리는 파일을 격리하는 한 가지 방법입니다. 둘 이상의 작업공간이 동일한 관리 작업 트리를 참조할 수 있으며 Paseo는 마지막 작업공간이 아카이브된 후 해당 작업 트리를 제거합니다.

## 작업공간 만들기

앱이나 CLI에서 작업공간을 생성할 수 있습니다.

```bash
paseo workspace create --isolation local --path ~/dev/my-app --title main
paseo workspace create --isolation worktree --path ~/dev/my-app --base origin/main
```

에이전트를 바로 시작하지 않고도 작업공간을 생성할 수도 있습니다. 작업 공간은 작업 디렉토리가 준비된 상태로 여전히 존재합니다. 터미널을 열고, 서비스를 실행하고, 파일을 찾아본 다음 나중에 에이전트를 시작할 수 있습니다.

어느 쪽이든 작업 공간이 존재하면 더 많은 세션을 추가할 수 있습니다. 에이전트와 함께 터미널을 열고, 두 번째 에이전트를 시작하여 변경 사항을 검토하거나, 브라우저 탭을 열어 로컬 서비스를 확인하세요. 모든 세션은 동일한 작업 공간 내에서 탭으로 표시됩니다.

에이전트 생성과 작업 영역 생성은 별도의 작업입니다. 특정 기존 작업 영역에 에이전트를 추가하려면 작업 영역 ID를 전달하세요. 휴먼 셸의 `paseo run`은 새로운 로컬 작업 공간을 만듭니다. 하나의 에이전트가 이를 실행하면 Paseo는 호출자를 인식하고 호출자의 작업 공간에 하위 에이전트를 생성합니다.

## 작업 트리

Paseo의 모든 작업공간은 작업 디렉토리에 의해 지원됩니다. 해당 디렉터리가 git 작업 트리이면 각 작업에 대해 별도의 분기와 격리된 환경이 제공됩니다.

설정 후크, 스크립트, 서비스 구성에 대한 자세한 내용을 보려면 [Git 작업 트리](/docs/worktrees)를 계속 진행하세요.
