# 허브 작동 방식

허브는 요청이 도착하는 위치를 에이전트가 실행되는 머신에 연결합니다.

```text
GitHub / Slack / Discord / manual request
                    ↓
                  Hub
        matches a project trigger
                    ↓
                workflow
          runs ordered agent steps
                    ↓
             Paseo daemon
             starts the agent
```

## 조각

- **연결**을 통해 Hub는 GitHub, Slack 또는 Discord에서 이벤트를 수신할 수 있습니다.
- **데몬**은 Paseo 데몬을 실행하는 등록된 머신입니다.
- **프로젝트**는 사용하는 연결 및 데몬을 사용하여 하나의 구성을 그룹화합니다.
- 워크플로 단계가 실행되는 **환경** 이름: 데몬, 해당 작업 디렉터리 및 선택적 작업 트리.
- **트리거**는 워크플로를 시작할 수 있는 공급자 이벤트와 허용되는 이벤트를 알려줍니다.
- **워크플로**는 트리거가 일치한 후 실행되는 순서가 지정된 단계 집합입니다.
- **단계**는 자체 프롬프트, 에이전트 선택, 자격 증명, 응답 기능 및 제한을 포함하여 하나의 에이전트 실행을 시작합니다.

구성은 프로젝트가 GitHub 소스를 사용할 때 `.paseo/hub.yml` 및 규칙에 따라 발견된 `.paseo/workflows/*.yml` 파일에 있습니다. 프로젝트에는 한 번에 하나의 활성 구성 개정이 있습니다.

## 이벤트부터 에이전트까지

1. 공급자가 허브에 이벤트를 보냅니다. GitHub와 Slack은 웹훅을 사용합니다. Discord는 게이트웨이 연결을 사용합니다. 수동 실행은 Hub API를 사용합니다.
2. 허브는 공급자 이벤트를 확인하고 저장소, 작업 공간 또는 길드와 같은 프로젝트 리소스를 식별합니다.
3. 허브는 필수 `from_users` 허용 목록을 포함하여 트리거와 해당 필터를 평가합니다.
4. 일치하는 트리거는 활성 구성 개정에서 워크플로 실행을 생성합니다.
5. 워크플로는 다음 단계를 평가합니다. 거짓 `if` 조건은 해당 단계를 건너뜁니다. true 조건은 구성된 데몬에서 시작됩니다.
6. 데몬은 에이전트를 시작하고 허브는 응답, 구조화된 출력, 상태 및 완료를 기록합니다.
7. 다음 단계에서는 완료된 단계의 출력을 확인합니다. 남은 단계가 없으면 워크플로 실행이 완료됩니다.

전체 구성은 [워크플로](/docs/hub/workflows)에 있습니다.

## 활성화

Hub는 번들을 동기화할 때 모든 소스 파일의 유효성을 검사하고 해당 참조를 확인합니다.

- `filters.repo`, `filters.workspace` 및 `filters.guild`은 조직의 연결을 통해 사용 가능한 리소스의 이름을 지정해야 합니다.
- `environment.daemon`은 등록된 데몬의 친숙한 슬러그와 일치해야 합니다.
- 단계 ID, 표현식, 입력 필터, 출력 스키마 및 기간이 유효해야 합니다.
- 모든 유한 환경 또는 명명된 에이전트 결과가 존재하고 검증되어야 합니다.
- 프롬프트 부분은 정확한 커밋에서 `.paseo/workflows/partials/` 아래로 해결되어야 합니다.

활성화에 실패하면 Hub는 이전 활성 개정을 유지합니다. 구성 탭에는 실패한 동기화와 해당 유효성 검사 오류가 표시됩니다. 활동은 마지막 활성 개정을 계속 반영합니다.

## 보안 경계

트리거에는 외부 소스 이벤트에 대한 비어 있지 않은 `from_users` 허용 목록이 필요합니다. 활성 구성을 변경할 수 있는 사람은 누구나 프로젝트에서 사용할 연결, 데몬, 에이전트 기능을 선택할 수 있으므로 구성 저장소를 보호하세요.

이러한 제어는 에이전트를 샌드박싱하거나 입력을 안전하게 만들지 않습니다. 호스트 경계, 공급자 기본 정책 및 심층 방어 지침은 [허브 보안](/docs/hub/security)을 참조하세요.

GitHub 자격 증명은 트리거에 의해 암시되지 않습니다. 단계는 실행을 시작한 모든 항목에서 [`github` 블록](/docs/hub/github)을 선언하는 경우에만 GitHub 권한을 보유합니다.
