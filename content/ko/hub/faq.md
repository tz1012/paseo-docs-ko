# 허브 FAQ

## Paseo를 사용하려면 허브가 필요한가요?

아니요. Paseo는 에이전트 없이 컴퓨터에서 에이전트를 실행합니다. Hub는 단일 데몬이 자체적으로 수행할 수 없는 작업, 즉 외부 활동에서 에이전트 시작, 버전이 지정된 구성, 실행된 항목에 대한 공유 기록, 팀 액세스를 추가합니다.

## 하나의 조직이 여러 GitHub 조직을 연결할 수 있나요?

그렇습니다. 연결은 조직에 속하며 추가하는 연결 수에는 제한이 없습니다. 각각은 자체 슬러그를 얻습니다.

## 내 작업을 어떻게 프로젝트로 분할해야 하나요?

이미 분할한 방식은 제품당 하나, 팀당 하나, 저장소당 하나입니다. 프로젝트는 하나의 환경 및 트리거 세트를 소유하므로 함께 구성하고 배포해야 하는 모든 항목은 동일한 프로젝트에 속합니다.

프로젝트는 조직의 연결과 데몬을 공유하므로 새 프로젝트가 GitHub를 연결하거나 데몬을 다시 등록하는 것을 의미하지 않습니다.

## 두 프로젝트가 동일한 저장소를 감시할 수 있나요?

그렇습니다. 둘 다 실행됩니다. 저장소는 프로젝트의 소유가 아닙니다.

## 감시 중인 저장소가 아닌 다른 곳에 구성을 적용할 수 있나요?

그렇습니다. `filters.repo`은 조직이 접근할 수 있는 모든 저장소의 이름을 지정할 수 있으므로 개인 저장소는 공용 저장소를 감시하는 워크플로에 대한 `.paseo` 번들을 보유할 수 있습니다. 번들이 조직의 연결, 데몬, 에이전트 및 출력을 선택하므로 푸시 액세스를 보호합니다.

## 트리거는 이제 어디로 가나요?

각 트리거와 해당 순서가 지정된 단계는 하나의 직접 `.paseo/workflows/*.yml` 파일에 있습니다. `hub.yml`에는 명명된 환경과 에이전트만 포함됩니다. 허브는 모놀리식 `triggers` 구성을 변환하는 대신 거부합니다.

## 대시보드에서 구성을 편집할 수 있나요?

예, 수동 소스를 사용합니다. GitHub 소스를 사용하는 프로젝트는 저장소가 정보 소스이므로 대시보드에서 읽기 전용입니다. 수동으로 전환하면 활성 개정이 편집기에 복사되고 동기화가 중지됩니다.

## 누가 에이전트를 트리거할 수 있나요?

트리거의 `from_users`에 나열된 사용자만. 필수 항목이며 비워둘 수 없습니다.

## 데몬이 오프라인이면 어떻게 되나요?

디스패치가 실패하고 이벤트가 실패로 기록됩니다. 대기 중인 항목이 없으므로 데몬이 돌아오면 다시 트리거하세요.

## 로그아웃하면 데몬 연결이 끊어지나요?

아니요. 저장된 CLI 로그인은 인간 조직 자격 증명입니다. 등록된 데몬에는 자체 관계 자격 증명이 있습니다. 대화형 `paseo hub logout`은 동일한 허브와 관련된 데몬 연결을 끊도록 제안합니다. 거부는 일반적인 현상이며, `--disconnect-daemon`을 전달하지 않으면 JSON 또는 비대화형 로그아웃이 절대로 연결 해제되지 않습니다.

## 에이전트가 Slack이나 Discord에 답장을 보낼 수 있나요?

그렇습니다. 단계에 `allow_outputs`을 입력하고 프롬프트에서 에이전트에게 `hub.reply`으로 호출하라고 지시하세요. [에이전트에게 어떤 도구를 호출할지 알려주세요](/docs/hub/workflows#tell-the-agent-which-tool-to-call) 메시지가 표시됩니다. 응답 제한 및 `required`은 [출력 기능 참조](/docs/hub/configuration/hub-yml#output-capability)에 있습니다.

GitHub에는 응답 기능이 없습니다. 단계에 [`github` 블록](/docs/hub/github)을 제공하면 에이전트가 `gh` CLI를 통해 작동합니다.

## GitHub 없이 사용할 수 있나요?

그렇습니다. 수동 구성 및 Discord 또는 Slack 연결이 있는 프로젝트는 제대로 작동합니다. GitHub는 저장소에서 구성을 동기화하려는 경우에만 필요합니다.
