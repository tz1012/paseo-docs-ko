# 오케스트레이션

Paseo 오케스트레이션은 Paseo 데몬에 대한 코딩 에이전트 제어를 제공합니다. 에이전트는 사용자가 구성한 모든 공급자와 모델을 검색하고, 작업 영역을 생성하고, 다른 에이전트를 시작하고, 후속 조치를 보내고, 하트비트 또는 일정을 생성할 수 있습니다. 동일한 작업이 Paseo 앱에 계속 표시됩니다.

## 기본 하위 에이전트와 Paseo 하위 에이전트

기본 하위 에이전트와의 가장 중요한 차이점은 **Paseo 하위 에이전트가 공급자 경계를 넘을 수 있다는 것**입니다.

```text
Claude Code (Fable 5) => Codex (GPT-5.6)
Codex (GPT-5.6) => Grok Build
Cursor => Claude Code (Fable 5)
```

기본 하위 에이전트는 하나의 공급자에 속합니다. Claude Code는 Claude Code 하위 에이전트를 출시합니다. Codex는 Codex 하위 에이전트를 출시합니다. 상위 공급자가 전체 작업 자체를 처리할 수 있는 경우 유용합니다.

Paseo 하위 에이전트는 Paseo 데몬이 관리하는 전체 에이전트입니다. 오케스트레이터는 구성된 공급자 및 모델을 선택하고 작업자를 현재 작업 공간에 유지하거나 작업을 위해 생성된 다른 작업 공간에 배치할 수 있습니다. 하나의 모델을 계획하고, 다른 모델을 구현하고, 다른 모델을 검토하려는 경우 이를 사용하세요.

|                      | 기본 하위 에이전트 | Paseo 하위 에이전트 |
| ------- | ---------------------------- | ------------------------------------- |
| 공급자 | 상위와 동일한 제공자 | Paseo |
| 작업 디렉토리 | 상위 공급자가 관리 | 현재 또는 명시적으로 선택된 작업공간 |
| 수명주기 | 상위 제공업체 소유 | Paseo가 관리합니다. 후속 조치를 받을 수 있습니다 |
| 검사하는 곳 | 하위 에이전트 트랙의 읽기 전용 타임라인 | 하위 에이전트 트랙의 전체 에이전트 세션 |
| | 빠른 공급자 기반 위임 | 공급자 간 작업 및 명시적인 작업 공간 제어 |

## 시도해 보세요

**설정 → 호스트 → 에이전트**를 연 다음 **Paseo 도구 활성화**를 켭니다. 새 에이전트를 시작하거나 기존 에이전트를 다시 로드하여 도구를 받습니다.

그러면 자연스럽게 물어보세요.

```text
Stay as the orchestrator. Use Paseo to find my available Codex models, then
create a worktree-isolated workspace, then launch a GPT-5.6 subagent there. Ask
it to implement the parser change, run the focused tests, and report back here.
```

오케스트레이터는 공급자와 모델 ID를 검색하고 작업자를 시작한 다음 완료되면 알림을 받습니다. 그동안 오케스트레이터와 계속 대화할 수 있습니다.

에이전트 생성에는 하나의 기본값이 있습니다. 에이전트가 작업 영역 ID 없이 다른 에이전트를 생성하면 새 에이전트는 동일한 작업 영역에 있는 하위 에이전트가 됩니다. 작업 영역 ID를 전달하면 상위 에이전트가 아닌 하위 에이전트가 작동하는 위치가 변경됩니다.

## 작품이 등장하는 곳

생성된 작업은 작곡가 위의 **하위 에이전트 트랙**에 표시됩니다. 실시간 대화를 읽으려면 행을 엽니다.

두 종류의 하위 에이전트가 모두 여기에 나타납니다.

- **Paseo 하위 에이전트**는 전체 에이전트 세션으로 열립니다. 직접 대화하거나, 설정을 변경하거나, 보관할 수 있습니다.
- **기본 공급자 하위 에이전트**는 읽기 전용 타임라인으로 열립니다. 귀하는 해당 작업을 검사할 수 있지만 해당 공급자는 해당 수명 주기를 소유합니다.

작업 공간 간 하위 에이전트는 여전히 상위 하위 에이전트 트랙에 속합니다. Paseo는 또한 작업 공간을 열어 작업이 비어 있는 작업 공간에 숨겨지지 않도록 합니다. 하위 에이전트를 최상위 에이전트로 전환하려면 앱에서 또는 `paseo agent detach`을 사용하여 수동으로 분리하세요. 분리는 에이전트 생성 모드가 아닙니다.

상담사가 백그라운드 작업이 실행 중이라고 하는데 트랙이 비어 있으면 Paseo를 업데이트하세요. 공급자가 만든 하위 에이전트 타임라인에는 Paseo 0.1.107 이상이 필요합니다.

## 상담원의 지속적인 작업 유지

하트비트는 cron 주기에 따라 동일한 에이전트로 프롬프트를 다시 보냅니다. 에이전트가 라이브 작업을 계속 재평가해야 하는 경우 하나를 사용하십시오. 리팩터링을 계속하고, CI를 관리하고, 배포를 관찰하거나, 외부 시스템 변경 후 재시도하십시오.

상담원에게 직접 물어보세요.

```text
Use Paseo to create a heartbeat every 10 minutes. Keep checking this PR, fix any
new CI failures, and stop when all checks pass or after two hours.
```

기본 [`/paseo` 오케스트레이션 기술](/docs/skills)은 에이전트에게 하트비트 생성 방법을 가르치므로 물어보기만 하면 됩니다. 하트비트는 현재 대화를 계속합니다. a [일정](/docs/schedules)은 일일 분류와 같은 독립형 크론 스타일 작업에 더 좋습니다.

프롬프트에서 MCP 도구의 이름을 지정할 필요가 없습니다. 작업 흐름을 요청하세요. 상담원은 아래 도구를 사용합니다.

복사 가능한 프롬프트의 경우 [공통 워크플로](/docs/orchestration-workflows), 패키지 워크플로의 경우 [오케스트레이션 기술](/docs/skills), 전체 도구 카탈로그의 경우 [MCP 참조](/docs/mcp)를 계속 진행하세요.
