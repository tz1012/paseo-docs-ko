# 보안

Paseo는 Docker와 유사한 클라이언트-서버 아키텍처를 따릅니다. 데몬은 컴퓨터에서 실행되고 코딩 에이전트를 관리합니다. 클라이언트(모바일 앱, CLI 또는 웹 인터페이스)는 데몬에 연결하여 해당 에이전트를 모니터링하고 제어합니다.

귀하의 코드는 귀하의 컴퓨터를 떠나지 않습니다. Paseo는 개발 환경에 직접 연결되는 로컬 우선 도구입니다.

## 아키텍처

Paseo 데몬은 에이전트를 실행하려는 노트북, Mac Mini, VPS, Docker 컨테이너 등 어디에서나 실행할 수 있습니다. 데몬은 연결을 수신하고 에이전트 수명 주기를 관리합니다.

클라이언트는 WebSocket을 통해 데몬에 연결됩니다. 이 연결을 설정하는 방법에는 두 가지가 있습니다.

- **릴레이 연결(권장)**, 데몬은 아웃바운드로 릴레이 서버에 연결하고 클라이언트는 그곳에서 이를 만납니다. 열린 포트가 필요하지 않습니다.
- **직접 연결**, 데몬은 네트워크 주소를 수신하고 클라이언트는 직접 연결합니다.

## 릴레이 연결(권장)

릴레이는 휴대폰에서 연결하는 가장 간단한 방법입니다. VPN 설정, 포트 전달, 방화벽 구성이 필요하지 않습니다. 데몬은 localhost나 소켓 파일에 바인딩된 상태로 있을 수 있으며, _outbound_를 릴레이에 연결하고 휴대폰이 그곳에서 이를 충족합니다. 공식 릴레이 서버는 [getpaseo/paseo-relay](https://github.com/getpaseo/paseo-relay)의 오픈소스 Elixir 서비스입니다.

새로운 설치에서는 릴레이가 꺼집니다. `paseo`, `paseo daemon pair` 또는 Paseo Desktop에서 장치를 페어링하면 Paseo는 장치를 활성화하기 전에 묻습니다. 릴레이를 활성화하지 않도록 선택하면 직접 TCP, Tailscale 또는 기타 VPN 연결에 데몬을 사용할 수 있으며 페어링 QR 코드가 생성되지 않습니다. 대화형 프롬프트 없이 옵트인하려면 CLI 페어링 또는 시작 명령과 함께 `--relay`을 사용하세요.

> **릴레이는 신뢰할 수 없도록 설계되었습니다.** 휴대폰과 데몬 사이의 모든 트래픽은 엔드투엔드 암호화됩니다. 릴레이 서버는 감지 없이 ​​메시지를 읽거나, 코드를 보거나, 트래픽을 수정할 수 없습니다. 릴레이가 손상되더라도 데이터는 계속 보호됩니다.

### 작동 방식

1. 데몬은 영구 ECDH 키 쌍을 생성하여 `$PASEO_HOME/daemon-keypair.json`에 저장합니다.
2. QR 코드를 스캔하거나 페어링 링크를 클릭하면 휴대폰이 데몬의 공개 키를 수신합니다.
3. 휴대전화는 자체 공개 키를 사용하여 핸드셰이크 메시지를 보냅니다. 데몬은 이 핸드셰이크가 완료될 때까지 어떤 명령도 수락하지 않습니다.
4. 양측은 각자의 Curve25519 키와 상대방의 공개 키를 결합한 다음, 결과로 얻은 NaCl
   `box` 채널을 사용해 XSalsa20-Poly1305로 보호된 페이로드를 전송합니다.

릴레이는 IP 주소, 타이밍, 메시지 크기 및 세션 ID만 볼 수 있습니다. 메시지 내용을 읽거나, 메시지를 위조하거나, 핸드셰이크를 관찰하여 암호화 키를 파생할 수 없습니다.

### 릴레이가 당신을 공격할 수 없는 이유

데몬은 명령을 처리하기 전에 유효한 암호화 핸드셰이크가 필요합니다. 손상된 릴레이는 다음을 수행할 수 없습니다.

- **명령 보내기**, 휴대폰의 개인 키가 없으면 핸드셰이크를 완료할 수 없습니다.
- **트래픽 읽기**, 페어링된 엔드포인트만 NaCl `box` 페이로드를 열 수 있습니다.
- **메시지 위조**, 인증 암호는 변조된 페이로드를 거부합니다.
- **오래된 메시지 재생**, 각 세션에서 새로운 암호화 키가 파생됩니다.

### 신뢰 모델

QR 코드 또는 페어링 링크가 트러스트 앵커입니다. 여기에는 암호화된 연결을 설정하는 데 필요한 데몬의 공개 키가 포함되어 있습니다. 비밀번호처럼 취급하고 공개적으로 공유하지 마세요.

## 직접 연결

기본적으로 데몬은 `127.0.0.1:6767`(localhost만 해당)에서 수신 대기합니다. 이는 로컬 CLI 사용에는 안전하지만 휴대폰이나 다른 장치에서는 연결할 수 없습니다.

릴레이 및 Tailscale 설정 지침은 [연결](/docs/connectivity)을 참조하세요.

### 소켓 파일(CLI에만 해당)

최대 격리를 위해 TCP 포트 대신 Unix 소켓 파일을 수신하도록 데몬을 구성할 수 있습니다. 이렇게 하면 네트워크 액세스가 완전히 방지되며 동일한 시스템의 프로세스만 연결할 수 있습니다. CLI는 이 모드를 지원하지만 모바일 앱과 웹 인터페이스에는 네트워크 연결이 필요합니다.

### VPN 액세스

로컬 네트워크 외부에서 직접 연결을 원할 경우 [Tailscale](https://tailscale.com)과 같은 VPN을 사용하세요. VPN은 트래픽을 암호화하고 데몬을 공용 인터넷에서 차단합니다. 데몬을 VPN 주소에 바인딩하고 Paseo 비밀번호를 설정한 다음 해당 주소를 클라이언트에 직접 연결로 추가하세요.

### 0.0.0.0에 바인딩

> **경고:** `0.0.0.0`에 바인딩하면 공용 Wi-Fi 및 로컬 네트워크를 포함한 모든 네트워크 인터페이스에서 데몬에 연결할 수 있습니다. 이로 인해 데몬이 무단 액세스에 노출될 수 있습니다. 모든 인터페이스에 바인딩해야 하는 경우 적절한 방화벽 규칙이 있는지 확인하고 `hostnames` 구성을 검토하세요.

## DNS 리바인딩 보호

**CORS는 완전한 보안 경계가 아닙니다.** 요청할 수 있는 브라우저 원본을 제어하지만 악의적인 웹 사이트가 해당 도메인을 로컬 컴퓨터로 확인(DNS 리바인딩)하는 것을 방지하지는 않습니다.

Paseo는 호스트 허용 목록을 사용하여 수신 요청의 `Host` 헤더를 검증합니다. 인식할 수 없는 호스트에 대한 요청은 거부됩니다.

`config.json`에서 `daemon.hostnames`을 통해 구성합니다.

- 기본값(`[]`): `localhost`, `*.localhost` 및 모든 IP 주소를 허용합니다.
- `['.example.com']`: `example.com` 및 모든 하위 도메인과 기본값을 허용합니다.
- `true`: 모든 호스트 허용(권장하지 않음)

## 비밀번호 인증

기본적으로 데몬의 수신 주소에 연결할 수 있는 사람은 누구나 연결할 수 있습니다. localhost에서는 괜찮습니다. 로컬 프로세스만 액세스할 수 있습니다. 그러나 네트워크 인터페이스(예: LAN IP 또는 `0.0.0.0`)에 바인딩하거나 로컬 네트워크를 완전히 신뢰하지 않는 경우 비밀번호를 요구할 수 있습니다.

비밀번호가 구성되면 모든 HTTP 요청에는 `Authorization: Bearer <password>` 헤더가 포함되어야 하며 모든 WebSocket 연결은 하위 프로토콜을 통해 인증해야 합니다. 인증되지 않은 요청은 `401 Unauthorized` 응답을 받습니다. `/api/health` 활성 엔드포인트만 제외되므로 프로세스 감독자와 로드 밸런서는 자격 증명 없이 프로브할 수 있습니다.

[번들 웹 UI](/docs/web-ui)를 활성화하면 정적 파일도 비밀번호 없이 제공되므로 로그인 화면이 렌더링될 수 있습니다. 이는 의도적으로 설계된 것으로, 에이전트 데이터가 반환되거나 명령이 실행되기 전에 API 및 WebSocket에 여전히 인증이 필요합니다. 페이지 뒤의 데이터가 보호되도록 데몬을 네트워크에 바인딩하기 전에 비밀번호를 설정하세요.

비밀번호는 `config.json`에 bcrypt 해시로 저장되며 데몬은 비밀번호를 일반 텍스트로 저장하지 않습니다. 설정 지침은 [구성](/docs/configuration#password-authentication)을 참조하세요.

### 비밀번호 인증이 수행하는 것과 수행하지 않는 것

- **기능:** 승인되지 않은 클라이언트가 네트워크를 통해 데몬에 도달할 수 있더라도 에이전트를 제어하지 못하도록 방지합니다.
- **하지 않음:** 트래픽을 암호화합니다. 비밀번호 인증은 기밀이 아닌 액세스를 보호합니다. 신뢰할 수 없는 네트워크를 통해 암호화된 연결이 필요한 경우 릴레이(종단 간 암호화 제공) 또는 Tailscale과 같은 VPN을 사용하세요.

### 언제 사용하나요?

- 데몬을 LAN 또는 Tailscale 주소에 바인딩하고 연결할 수 있는 사람을 제한하려고 합니다.
- 로컬 네트워크(공유 사무실, VPN을 사용하는 공용 Wi-Fi 등)를 완전히 신뢰하지 않습니다.
- 역방향 프록시를 통해 데몬을 노출하고 있으며 추가 인증 계층이 필요합니다.

우리는 여전히 모바일 액세스를 위한 릴레이를 권장합니다. 이 릴레이는 인증과 즉시 사용 가능한 엔드투엔드 암호화를 결합합니다. 비밀번호 인증은 주로 릴레이 없이 액세스 제어를 원하는 직접 LAN 또는 VPN 연결에 유용합니다.

## Docker 자체 호스팅

공식 Docker 이미지는 하나의 컨테이너에서 데몬과 번들 웹 UI를 실행합니다. 컨테이너 내부의 `0.0.0.0:6767`에 바인딩되므로 Docker 포트 게시 및 역방향 프록시가 정상적으로 작동합니다.

Docker 배포의 경우:

- 포트를 LAN, VPN 또는 공용 주소에 게시하기 전에 `PASEO_PASSWORD`을 설정하세요.
- localhost 외부의 브라우저 액세스를 위해 역방향 프록시에서 HTTPS를 사용합니다.
- 컨테이너에 도달하는 데 사용하는 DNS 이름에 대해 `PASEO_HOSTNAMES`을 설정합니다.
- 에이전트가 읽고 쓸 수 있어야 하는 리포지토리로 `/workspace` 마운트 범위를 유지합니다.
- `/home/paseo`을 민감한 항목으로 처리합니다. 데몬 상태 및 공급자 자격 증명을 포함할 수 있습니다.

이미지는 루트가 아닌 `paseo` 사용자로 데몬을 실행하고 에이전트를 실행하지만 컨테이너 사용자 격리는 신중한 마운트를 대체할 수 없습니다. 에이전트는 컨테이너에 탑재된 모든 코드와 자격 증명에 계속 액세스할 수 있습니다.

Compose 및 역방향 프록시 예시는 [Docker](/docs/docker)를 참조하세요.

## 에이전트 인증

Paseo는 에이전트 CLI(Claude Code, Codex, OpenCode)를 래핑하지만 인증을 관리하지는 않습니다. 각 에이전트 공급자는 자체 자격 증명을 처리합니다.

- **Claude Code**는 `~/.claude/`에 저장된 Anthropic의 OAuth 흐름을 통해 인증합니다.
- **Codex**, OpenAI API 키 또는 OAuth 세션을 사용합니다.
- **OpenCode**, 공급자별 API 키를 통해 구성됨

Paseo는 공급자 API 키를 저장하거나 전송하지 않습니다. 에이전트는 기존 자격 증명을 사용하여 사용자 컨텍스트에서 실행됩니다.

## 허브 ID 및 자격 증명

Hub CLI 로그인과 데몬 등록은 별도의 ID입니다. `paseo hub login [origin]`은 정규화된 허브 원본을 기준으로 `PASEO_HOME` 아래의 개인 파일에 내구성 있는 조직 범위의 인간 자격 증명을 저장합니다. 저장된 자격 증명은 다른 원본으로 전송되지 않습니다. `PASEO_HOME`을 민감한 로컬 상태로 보호하세요.

Hub CLI 자격 증명은 전달자 비밀입니다. 원격 허브 원본은 HTTPS를 사용해야 합니다. 일반 텍스트 HTTP는 루프백 개발 원본(`localhost`, `127.0.0.1` 및 `[::1]`)에만 허용됩니다.

`paseo hub connect [origin]`은 해당 자격 증명이나 명시적 API 키를 사용하여 단기 일회성 등록 토큰을 요청합니다. 데몬은 토큰을 교환하고 독립적으로 생성된 관계 자격 증명을 유지합니다. CLI에서 로그아웃해도 데몬 권한이 자동으로 제거되지는 않습니다. 대화형 로그아웃은 로그인을 삭제하기 전에 허용된 모든 동일 출처 데몬 연결 해제를 완료합니다. JSON 및 비대화형 사용에서 `logout`은 메시지를 표시하거나 연결을 끊지 않습니다. 자동화가 두 ID를 모두 제거하려는 경우에만 `--disconnect-daemon`을 전달하세요.

`--api-key` 및 `PASEO_HUB_API_KEY`은 지속되지 않고 저장된 로그인을 재정의합니다. 자동화를 위해 환경 또는 비밀 관리자 삽입을 선호하고, 로컬 프로세스 목록이나 셸 기록이 다른 사용자에게 표시되는 경우 명령줄 플래그를 피하세요.

## 추천

- 모바일 액세스에 **릴레이를 사용**하세요. 이는 가장 간단한 옵션이며 모든 트래픽이 종단 간 암호화됩니다.
- **QR 코드를 비밀번호처럼 취급하세요**, 페어링 제안을 받은 사람은 누구나 데몬에 연결할 수 있습니다.
- **비밀번호 설정** 네트워크 주소에 바인딩하면 승인되지 않은 클라이언트가 에이전트를 제어하는 것을 방지할 수 있습니다.
- **비밀번호 없이는 절대 0.0.0.0에 바인딩하지 마세요**, 비밀번호가 없으면 네트워크의 모든 장치에 연결할 수 있습니다
- **Docker 범위는 긴밀하게 마운트됩니다**, 에이전트는 마운트된 작업 영역 및 공급자 자격 증명에 액세스할 수 있습니다.
- **데몬을 계속 업데이트하세요**, 보안 개선 사항이 정기적으로 출시됩니다.
- **허브 구성 분기를 보호**, `.paseo` 번들에 대한 액세스 푸시로 해당 프로젝트가 도달할 수 있는 내용을 제어합니다. [허브 작동 방식](/docs/hub/concepts)을 참조하세요.
