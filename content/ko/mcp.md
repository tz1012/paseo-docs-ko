# MCP 참조

[Paseo 도구를 활성화](/docs/orchestration#get-started)해 에이전트에 이 카탈로그를 제공하세요. 자연어로 결과를 요청하거나 아래 도구 인터페이스를 사용하세요.

## 구성

| 설정 | 기본값 | 목적 |
| ----------------------------- | ------- | -------------------------------------------------- |
| `daemon.mcp.enabled` | `true` | MCP 서버를 실행합니다. |
| `daemon.mcp.injectIntoAgents` | `false` | Paseo가 시작한 에이전트에 Paseo 도구 접근 권한을 제공합니다. |

공급자에 따라 Paseo는 기본 도구 인터페이스 또는 MCP를 통해 도구를 제공합니다. 기능은 어느 쪽이든 동일합니다. 주입 설정을 변경한 후 새 에이전트를 시작하거나 기존 에이전트를 다시 로드하세요.

## 공급자별 Paseo 도구 제한

에이전트 프로필마다 서로 다른 Paseo 도구를 제공해야 할 때는 공급자 정책을 사용하세요. 도구 주입을 전역으로 활성화한 다음 실제로 실행하는 정확한 공급자 ID에 `paseoTools`를 추가합니다.

```json
{
  "$schema": "https://paseo.sh/schemas/paseo.config.v1.json",
  "version": 1,
  "daemon": {
    "mcp": {
      "enabled": true,
      "injectIntoAgents": true
    }
  },
  "agents": {
    "providers": {
      "codex-lead": {
        "extends": "codex",
        "label": "Codex Lead"
      },
      "codex-worker": {
        "extends": "codex",
        "label": "Codex Worker",
        "paseoTools": {
          "disabledTools": ["create_agent", "send_agent_prompt", "kill_agent"]
        }
      },
      "codex-isolated": {
        "extends": "codex",
        "label": "Codex Isolated",
        "paseoTools": {
          "enabled": false
        }
      }
    }
  }
}
```

`~/.paseo/config.json`을 편집한 뒤 `paseo reload`를 실행하고 새 에이전트를 시작하거나 기존 에이전트를 다시 로드하세요. 실행 중인 세션은 시작할 때 받은 카탈로그를 유지합니다.

`paseoTools`를 생략하면 전체 카탈로그가 활성화됩니다. 카탈로그를 제거하려면 `enabled`를 `false`로 설정하고, 선택한 도구를 제거하려면 정확한 도구 ID를 `disabledTools`에 나열하세요. 사용자 지정 프로필은 이 정책을 `extends`에서 상속하지 않으므로 각 사용자 지정 공급자 ID를 별도로 구성해야 합니다.

브라우저 도구를 사용하려면 여전히 브라우저 도구가 활성화되어 있고 브라우저 호스트가 연결되어 있어야 합니다. 음성 전용 `speak` 도구는 이 정책과 별개입니다.

이 설정은 에이전트에 제공되는 카탈로그를 제한합니다. 셸을 통해 호스트에 접근할 수 있는 에이전트에 대한 보안 경계는 아닙니다.

## 정신 모델

작업 공간은 작업이 수행되는 위치를 결정합니다. 대리인의 친족이 작품의 소유자를 결정합니다.

- `workspaceId` 없이 `create_agent`을 호출하는 에이전트는 자체 작업공간에서 하위 에이전트를 얻습니다.
- `workspaceId`을 전달하면 하위 에이전트를 상위 에이전트에서 분리하지 않고 다른 작업 영역에 배치합니다.
- 작업 공간이 없는 최상위 MCP 호출자는 새로운 로컬 작업 공간을 얻습니다.
- 워크트리 격리, 특정 브랜치, 풀 리퀘스트 체크아웃이 필요한 경우 먼저 워크스페이스를 생성하세요.

MCP는 에이전트 분리 도구를 노출하지 않습니다. 분리는 앱이나 CLI에서 수동으로 수행되는 사용자 작업입니다.

## 도구

### 에이전트

| 도구 | 기능 |
| ------- | -------------------------------------------------------------------------- |
| `create_agent` | 에이전트를 생성하고 선택적으로 `workspaceId`을 사용하여 기존 작업 영역에 배치합니다.     |
| `send_agent_prompt` | 기존 에이전트의 `agentId`와 `prompt`를 사용해 프롬프트를 보냅니다. |
| `get_agent_status` | 에이전트의 최신 스냅샷을 반환합니다.                                                |
| `list_agents` | 최근 에이전트를 컴팩트 메타데이터로 나열합니다.                                                 |
| `cancel_agent` | 에이전트의 현재 실행을 중단하지만 에이전트를 활성 상태로 유지합니다.                                  |
| `archive_agent` | 에이전트를 일시 삭제하고 활성 목록에서 제거합니다.                                |
| `kill_agent` | 에이전트 세션을 영구적으로 종료합니다.                                                 |
| `update_agent` | 에이전트 이름, 라벨 또는 모드/모델/사고/기능과 같은 런타임 설정을 업데이트합니다. |
| `get_agent_activity` | 최근 에이전트 타임라인 항목을 선별된 요약으로 반환합니다.                              |
| `set_agent_mode` | 에이전트의 세션 모드를 전환합니다.                                                         |

### 작업공간

| 도구 | 기능 |
| ------ | ---------------------------------------------------------------------------------------- |
| `create_workspace` | 로컬 또는 작업 트리 격리 작업공간을 만듭니다. 작업 트리는 분기하거나 분기를 확인하거나 PR을 수행할 수 있습니다. |
| `list_workspaces` | 활성 작업공간과 해당 디렉터리 및 격리를 나열합니다.                                           |
| `rename_workspace` | 현재 또는 지정된 작업공간의 사용자 표시 이름을 변경합니다.                                   |
| `archive_workspace` | 작업공간과 해당 작업공간이 소유한 세션을 보관합니다.                                                         |

작업 트리 격리의 경우 `create_workspace`은 앱과 동일한 유용한 선택(베이스에서 분기, 기존 분기 확인 또는 끌어오기 요청 확인)을 허용합니다. 작업 트리는 작업공간 수명 주기의 구현 세부 사항으로 남아 있습니다.

### 작업공간 스크립트

이러한 도구는 작업 영역의 `paseo.json`에 구성된 스크립트를 관리합니다. 각각에는 명시적인 `workspaceId`이 필요합니다. 시작 및 중지에도 구성된 `scriptName`이 필요합니다.

| 도구 | 기능 |
| ------------------------ | -------------------------------------------------------------------------- |
| `list_workspace_scripts` | 수명 주기, 터미널, 포트, 프록시 URL 및 상태 메타데이터와 함께 구성된 스크립트를 나열합니다. |
| `start_workspace_script` | Paseo의 관리형 실행 프로그램을 통해 구성된 스크립트를 시작하세요.                             |
| `stop_workspace_script` | 감독되는 터미널을 통해 실행 중인 스크립트를 중지합니다.                                  |

`paseo.json` 구성은 [Git 작업 트리](/docs/worktrees#scripts-and-services)를 참조하세요.

### 터미널

| 도구 | 기능 |
| ------- | -------------------------------------------------- |
| `list_terminals` | 하나의 작업 디렉터리 또는 모든 작업 디렉터리에 대한 터미널 세션을 나열합니다. |
| `create_terminal` | 작업 디렉터리에 대한 터미널 세션을 만듭니다.                           |
| `kill_terminal` | 터미널 세션을 종료합니다.                                                     |
| `capture_terminal` | 터미널 세션에서 일반 텍스트 출력을 캡처합니다.                           |
| `send_terminal_keys` | 터미널 세션에 텍스트 또는 특수 키 토큰을 보냅니다.                       |

### 일정 및 하트비트

둘 다 동일한 cron 엔진을 사용하지만 의도적으로 다른 인터페이스를 사용합니다.

| 도구 | 기능 |
| ------ | -------------------------------------------------- |
| `create_schedule` | 실행될 때마다 새 에이전트를 시작하는 크론 일정을 만듭니다.                 |
| `list_schedules` | 데몬이 관리하는 새 에이전트 일정을 나열합니다.                              |
| `inspect_schedule` | 일정과 해당 실행 기록을 검사합니다.                                      |
| `pause_schedule` | 활성 일정을 일시 중지합니다.                                                    |
| `resume_schedule` | 일시 중지된 일정을 재개합니다.                                                    |
| `update_schedule` | 일정의 크론, 프롬프트, 에이전트 설정, 제한 또는 기타 설정을 변경합니다. |
| `schedule_logs` | 일정에 대한 최근 실행 및 출력을 반환합니다.                                |
| `run_schedule_once` | cron을 변경하지 않고 하나의 새 에이전트 일정 실행을 시작합니다.                  |
| `delete_schedule` | 신규 에이전트 일정을 영구적으로 삭제합니다.                                     |
| `create_heartbeat` | 반복되는 cron 지원 프롬프트를 현재 에이전트로 보냅니다.                  |
| `delete_heartbeat` | 현재 에이전트의 하트비트 중 하나를 삭제합니다.                                |

MCP 하트비트는 임시적이므로 생성하거나 삭제합니다. 변경하려면 삭제하고 대체 항목을 만드세요. 일시 중지, 재개, 업데이트, 검사, 로그 및 한 번 실행은 새 에이전트 일정에만 적용됩니다.

### 에이전트 프로필

| 도구 | 기능 |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `list_profiles` | 호스트에 저장된 에이전트 프로필을 메모와 실행 설정을 포함해 반환합니다. 구성된 프로필이 없으면 빈 목록을 반환합니다. |

위임하기 전에 각 프로필의 `notes`를 읽고, 사용자가 지정한 프로필이나 작업에 맞는 프로필을 선택하세요. 설정 및 메모 예시는 [에이전트 프로필](/docs/agent-profiles)을 확인하세요.

`create_agent`에는 프로필 매개변수가 없으며 `provider/model` 쌍이 필요합니다. 프로필에 모델이 없으면 해당 공급자에 대해 `list_models`를 호출하고, 작업에 사용할 수 있는 모델을 선택한 후 시작하세요. 선택한 프로필의 값을 실행 요청에 적용합니다.

| 프로필 필드 | `create_agent` 필드 |
| ------------------------------- | --------------------------------------------------------------------------- |
| `provider`와 선택적 `model` | 저장되거나 검색된 모델 ID를 사용하는 `provider/model` 형식의 `provider` |
| `modeId` | `settings.modeId` |
| `thinkingOptionId` | `settings.thinkingOptionId` |
| `featureValues` | `settings.features` |
| `notes` | 오케스트레이터의 선택 지침이며, 실제 작업은 `initialPrompt`에 입력 |

없는 선택적 설정은 생략하세요. 적합한 프로필이 없으면 공급자 검색으로 사용 가능한 설정을 선택하세요.

### 제공업체

| 도구 | 기능 |
| ------------------ | ----------------------------------------------------------------- |
| `list_providers` | 구성된 에이전트 제공자, 가용성 및 모드를 나열합니다.         |
| `list_models` | 에이전트 제공업체의 모델을 나열합니다.                                |
| `inspect_provider` | 컴팩트 공급자 기능과 초안 기능 설정을 검사합니다. |

### 권한

| 도구 | 기능 |
| ------------- | ------------------------------------------------- |
| `list_pending_permissions` | 에이전트 전반에 걸쳐 보류 중인 권한 요청을 반환합니다. |
| `respond_to_permission` | 보류 중인 권한 요청을 승인하거나 거부합니다.     |

### 브라우저

브라우저 자동화는 선택 사항이며 탭 열기, 페이지 읽기, 클릭, 입력 및 스크린샷 촬영을 위한 도구를 추가합니다. [브라우저 도구 참조](/docs/browser-tools)를 확인하세요.

### 음성

| 도구 | 기능 |
| ------- | --------------------------------------------------------------- |
| `speak` | 데몬 관리 음성 출력을 통해 텍스트를 말합니다. 음성 지원 세션에서만 사용할 수 있습니다. |
